# Step 8: Project Reflection

### What Worked Well
Building the baseline RAG pipeline in a modular architecture proved very effective. Separating the offline indexing stages (`ingestion.py`, `chunking.py`, `embeddings.py`, and `vector_store.py`) from the online query stages (`retriever.py`, `generator.py`, and `pipeline.py`) made testing and debugging each component straightforward. Using local Ollama models (`nomic-embed-text` and `llama3.2:3b`) with ChromaDB persistent storage allowed the entire system to run completely offline with fast response times. Furthermore, prompt grounding in `generator.py` worked reliably: on-topic queries retrieved relevant chunks with low cosine distances and accurate citations, while out-of-domain questions correctly triggered the fallback response rather than hallucinating from the model's pre-trained weights.

### What Was Harder Than Expected
One challenging aspect was tuning the chunking hyperparameters and coordinating the offline indexing workflow with query time. Initially, with `chroma_db` excluded from Git via `.gitignore`, running the chat interface on a clean setup without first building the index caused retrieval errors. Ensuring that documents were properly loaded, sliced into chunks, and embedded before querying was essential. Additionally, choosing an appropriate chunk size (500 characters) and overlap (100 characters) required careful attention to avoid severing important technical definitions across chunk boundaries while keeping chunk representations focused enough for vector similarity matching.

### Future Improvement with Advanced RAG
To enhance retrieval quality in the future, I would implement **Cross-Encoder Re-ranking** (such as BGE-Reranker or Cohere Rerank) as a post-retrieval step. In the current naive RAG pipeline, dense embeddings perform well for general semantic matching, but bi-encoders independently embed queries and documents without cross-attention. This sometimes allows tangentially related chunks to rank ahead of more precise ones. Adding a re-ranker to score the top-10 candidate chunks before passing the top-3 to the generator would significantly improve context precision and answer quality.
